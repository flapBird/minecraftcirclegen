## 结论与证据边界

**GSC 确实出现严重曝光流失，但目前证据不足以确定根因，更不能直接认定“被 Google 惩罚”。** 最近七天与前七天相比，点击 16 → 0，曝光 792 → 24（-96.97%）。这首先需要检查索引状态、真实 Googlebot 抓取、受影响页面及排名变化。

目前公开站点没有表现出全站宕机、误加 noindex、canonical 集体指错或静态资源失效。本地功能检查发现若干可以复现的缺陷，另有业务脚本被 CSP 阻止的问题；这些问题值得修复，但尚未建立它们与本次搜索下降的因果关系。

本轮完成了全站公开 HTTP 检查、16 个工具的源码及现有测试覆盖检查、生产构建、4 项专项缺陷复现。**没有完成桌面和手机浏览器逐工具端到端验收，也没有完成 GSC 索引及处罚报表核查。** 内置浏览器控制连接不可用；通过 Chrome 成功读到概览和七天比较后，浏览器持续被同时操作，控制工具多次拒绝使用已改变的界面状态。不能把后面的源码检查写成视觉或实机体验验证。

## 3. 已确认的问题和修改方向

以下优先级针对功能与业务影响，不表示已确定 SEO 原因。

### A. 全站 CSP 与 Clarity / AdSense 加载代码冲突

**高优先级，线上响应头与源码共同确认。** `next.config.ts:8` 只允许本站、inline 和 googletagmanager 的脚本；`app/layout.tsx` 同时加载 `pagead2.googlesyndication.com` 与 `www.clarity.ms`。线上 HTTP 响应带着相同 CSP，HTML 也确实包含这两个集成，所以浏览器会阻止其外部脚本。`connect-src` 也没有 Clarity 收集端点。

影响：录屏/行为诊断不可依赖，广告集成也无法按预期加载。GA 的主域名已在允许列表，不应将本问题扩大为“所有统计都没了”。GSC 数据来自 Google Search，不依赖站内 Clarity 或 GA 脚本，因此该冲突不能直接解释 GSC 曝光骤降。

建议：按实际服务所需域名逐项修正策略，浏览器检查脚本及收集请求，然后确认工具仍可交互；不要直接移除 CSP。AdSense 当前使用 `beforeInteractive`，后续可评估是否有必要占用早期加载，但本轮没有测得它造成的性能回退。启用 Clarity 前同步更新现有隐私说明（当前仅具体说明 GA），这是产品说明的一致性问题，本报告不做法律合规判定。

### B. Shape 多边形受不可见高度控制

**P2，组件测试已复现。** `components/shape-generator/shape-generator.tsx:93` 的 `hasHeight` 列表缺少 polygon，但多边形算法使用 height，切换类型又保留原值。

复现：Rectangle → Height 33 → Polygon。结果显示 **21 × 33**，但页面不再提供 Height 控件。同样的多边形宽度和边数，可以因为用户此前用过的工具而生成不同结果。

建议：要么显示 Height 并明确允许拉伸，要么在选择 regular polygon 时按规则确定比例；不要保留不可见的自由参数。

### C. 字体工具缺少画布预算与输入边界

**P2，缺少限制及尺寸结果已复现；具体设备上的失败方式未实测。** `components/font-generator/font-generator.tsx:144` 的 textarea 没有长度上限；预览和导出直接用文本网格乘 Scale。

测试 500 个 `A`，默认参数得到 **36,048 × 144 px** 的画布；Scale 24 得到 **72,096 × 288 px**。1000 字符默认宽度达 72,048 px。长度、行数、尺寸与总像素数都缺少统一预算；更长内容会增加内存占用，并有触及浏览器画布限制、导出失败的风险。这里没有声称某个浏览器已经崩溃。

建议：预先估算最长边和总像素数；超过预算时换行、降低 Scale 或分图导出，并显示清楚的限制提示。另一个搜索意图问题是主文案写 “any text”，实现只保留有限的字符集，全部转大写；当前已有说明，但应让输入时的替换提示更明确。

### D. 附魔文字交换后重新打开会丢失内容

**P2，组件测试已复现。** `components/enchanting-table-translator/enchanting-table-translator.tsx:18` 将初始输入截到 4000 个 UTF-16 code unit；`swap()` 却直接接收可能更长的输出。

复现：输入 3000 个 `p` → 得到 6000 个字符的 `!¡` 序列 → Swap → 当前界面仍能反译出 3000 个 `p` → 将交换后的值重新作为分享页初始值打开 → 只剩 **2000 个 `p`**。这是前后状态不一致造成的静默丢失。

建议：输入、交换、分享与恢复使用同一套容量规则，超限时明确提示，避免在恢复入口悄悄 slice。多行 PNG 导出也没有高度上限，`toBlob` 失败时直接返回而没有提示，应一起处理。

### E. 几何工具快速分享可能带旧参数

**P2，使用可控计时器已复现；窗口为约 120 ms，普通慢速点击不一定触发。** `components/geometry-generator/geometry-generator.tsx:71` 延迟更新地址；`copyLink()` 在第 118 行直接复制当前浏览器地址。

复现：默认直径 21 → 改为 31 → 在地址同步前复制 → 分享链接仍恢复为 21，120 ms 后地址才变成 31。Circle/Oval/Sphere/Dome 共用此组件。

建议：复制动作直接从当前 shape/options 序列化 URL，保留无关查询参数与 hash，不依赖地址栏的延迟副作用。

### F. Pixel Art / Map Art 的施工输出不够完整

**产品缺口，源码确认，不是已完成的视觉审查。** `lib/image-art/export-image-art-png.ts` 导出彩色格子和网格/地图分界；界面只列出前 12 种材料，复制材料得到汇总计数。没有逐格方块 ID、坐标清单、颜色编号图例或格子点选读数。

用户得到的是“颜色图 + 总采购量”，面对相近颜色时难以知道每格该放哪种方块。尤其一张地图就是 128 × 128 格；对手工建造来说，缺少位置到材料的映射比没有更多介绍文字更影响完成任务。

建议优先加入坐标点选、编号图例、每张 128 × 128 地图的分块导出、CSV 方块坐标。schematic / Litematica 可以再评估，不必一次全做。页面已明确说不生成 map.dat / world / schematic，所以它属于能力不足，不能说现有页面承诺了这些格式却不兑现。地图实际颜色与游戏版本、方块映射仍需游戏内验证，本轮没有验证调色表精度。

### G. 大型 Shape 的交互计算与存储失败缺少保护

**待实机量化的风险。** Shape 128 的实心球由本次算法执行得到 **1,099,136 个方块、2,097,152 个网格单元**。3D 组件为占用单元构造字符串 Set 和坐标数组，并在绘制时判断外表面；切换 layer 也改变生成依赖。`useDeferredValue` 不能把同步计算搬离主线程。需要在低端手机量测，不能仅凭复杂度给出 INP 分数。

建议：几何与 layer 选择分离缓存，预计算外表面，必要时用 Worker；大尺寸限制实时 3D，保留准确的 2D 层图。

Banner 的 `persistSavedBanners()` 直接写 localStorage，没有处理写入异常；读取失败的 catch 又调用 removeItem，在禁用存储时也可能继续抛错。应将内存预览与持久保存失败分开，明确告知用户是否真的保存成功。此项是源码风险，本轮没有模拟浏览器拒绝存储的实机环境。

## 6. 接下来应按这个顺序处理

1. **先把下降定位到页面和日期。** 从 GSC DAYS 导出数据，固定完整的两组七天区间；以曝光差值排序 Pages 和 Queries，再按设备和国家对比。先检验大多数页面是否同日下降，不预先认定为全站事件。
2. **排除索引、处罚及抓取问题。** 读取 Manual actions、Security issues、Page indexing；对首页和损失最大的 3–5 个工具 URL 做 URL Inspection，记录 Google 选择的 canonical、最近抓取时间、允许索引状态、抓取结果与抓取到的内容。
3. **核对历史运维而不只看今天。** 查 9 月 22–24 日及前后的 Vercel 部署、Cloudflare WAF/挑战规则、DNS、Googlebot 403/429/5xx 和 Crawl stats。今天 200 不能证明发生下降时也正常。本轮没有这些历史日志。
4. **再判断算法因素。** 若多页仍正常索引、抓取和渲染正常，却在同一时间普遍失去查询曝光，算法或竞争力变化的解释才会更强。结合官方更新结束时间观察，避免每天改标题、频繁改结构或批量 noindex。
5. **修复明确功能缺陷，完善主力工具。** 先处理 CSP、静默丢失和不一致参数，再改善图片工具的施工输出，并实测手机上的大尺寸预览、输入、键盘、下载和返回导航。修复后记录部署时间，方便与后续 GSC 对照。
